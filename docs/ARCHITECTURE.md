# 架构说明

## 运行链路

```text
浏览器（中文界面）
  └─ 本机 HTTP 服务 app/server.py
       ├─ app/store.py → 只读 SQLite → 会话摘要与受限消息预览
       └─ app/bridge.py → OpenCode 桌面端 Node 运行时
                           └─ app/official-server.cjs → 已安装的服务模块
```

`main.py` 作为根目录入口调用应用。静态资源与后台脚本通过应用模块自身路径定位，启动时不依赖终端当前目录。

## 读取与修改

列表、筛选、消息预览和文本导出使用独立的只读 SQLite 连接。页面加载不扫描完整事件历史，不把大型附件送进浏览器。长文本和工具输出有明确的截断标记。

修改通过 OpenCode 自身接口进行，保留其事件发布和投影逻辑。后台管理服务按需启动。删除操作在服务启动后重新核对完整子会话范围，发送请求前确认桌面端已关闭，并检查操作结果。

## 本机边界

网页服务绑定 `127.0.0.1`。Host、Origin 和进程级防跨站令牌限制请求来源；静态路由采用明确允许的文件列表。

后台服务密码随机生成，通过标准输入传递，保存在进程内存中。网页不接收服务密码。管理器关闭时停止其创建的子进程。

对话内容使用 DOM 文本节点渲染。导出为受限的可读文本，不是包含附件和全部历史的恢复副本。

## 目录职责

- `app/`：应用包、网页资源和 OpenCode 桥接脚本。
- `tests/`：普通测试以及显式启用的本机集成测试。
- `docs/`：架构与变更说明。
- `.github/workflows/`：跨平台普通测试和语法检查。

## 兼容性

当前完整管理功能依赖 Windows OpenCode Desktop 1.19.5 的 Electron Node 运行时、打包模块及旧版数据库结构。普通测试使用合成数据，集成测试使用临时数据库。
